NR runtimes 310.8 and 310.9.16: static analysis (full technical)

Back to the report · ControlMask how-to · Noisy-domain NR feasibility

Written by Claude Opus 5.5 (Claude Code, high effort) on behalf of GrimsVerk, who skimmed it. The research, the test-build code changes, the measurements and this text are Claude's work.

Files: nvngx_dlssnr.dll 310.8.0.0 (CL 38718415, 165,840,496 bytes, SHA-256 4b8d19bc3eff58a084f5eca7489c921501c203450169fb82ff4f649a4482ba05) and 310.9.16.0 (CL 39025366, 266,424,944 bytes, SHA-256 2bc19bc09a7b89dd44f73e2ac0108fcc586e2154bdd0830f242f4f040e28789f).

Method:

  • PE inventory with pefile; strings (ASCII and UTF-16) diffed between versions.
  • Resource and weight-container parsing.
  • CUDA fatbins unpacked (zstd) to PTX and SASS ELF.
  • Full Ghidra 12.1.4 auto-analysis and decompile of both DLLs, image base 0x180000000.

"Seen in game" means the runtime's own NGX log confirmed it in The Witcher 3. The log was switched on with the __NGX_LOG_LEVEL environment variable, set in-process by the research build.

About line numbers. "l.NNNN" refers to a full decompile export (every function, Ghidra 12.1.4 default analysis, in address order). They only help if you make the same export. Function names and addresses (FUN_18xxxxxxx) are the stable reference: they are identical in any Ghidra project of the same file with the same base.

1. Summary

  • Exactly two models exist, and only 310.9.16 has both:
    • CC_Control_History_Blend_Quantize_With_Teacher_honest_tench_2026_07_04_22_30_weights ("honest tench"), resource WEIGHTS_HT, 147,695,410 bytes;
    • hnet-crazy-cuckoo-small-fp8 ("crazy cuckoo small"), resource WEIGHTS_CC_SMALL_FP8, 113,893,343 bytes.
  • WEIGHTS_HT is byte-identical in both DLLs. The ~100 MB growth of 310.9.16 is the new small model.
  • Presets:
    • 310.8 registers one preset (1 = honest tench); every value falls back to it, so Preset has no effect in 310.8.
    • 310.9.16 registers preset 1 (honest tench) and preset 2 (crazy cuckoo). 0/auto and every unknown value fall back to preset 2 (seen in game: "preset 0 is not available in this DLL build; falling back to shipping default preset 2 ('hnet-crazy-cuckoo-small-fp8')").
  • hnet-almond-eagle-11m is not a third model. It is the string the on-screen indicator draws in place of hnet-crazy-cuckoo-small-fp8 (strcmp + swap in FUN_18001c120). Nothing else references it.
  • No hidden presets, styles, models, weight files or debug views exist in either file. The weight registry, the descriptor list and the style tables were all read directly.
  • Style is 0/1/2 in both versions; values ≥ 3 clamp to 2. Style is a network input and a colour grade applied to the result (section 4).
  • New in 310.9.16: DLSSNR.MaskBlendMode (0-3). It only has an effect with a supplied DLSSNR.ControlMask and AutoMask on.
  • 310.9.16 dropped Ada (RTX 40): CreateFeature only accepts arch 0x1B0, and only sm_120 code ships. 310.8 accepts 0x190 and 0x1B0 and ships sm_89 SASS.
  • Both versions run both models in FP8. 310.8 also ships FP16 kernels, but they are unused.
  • Parameters with no effect in either version:
    • Depth / DepthInverted: the network's depth slot is hard-wired to null.
    • BidirectionalDistortionField: sets a telemetry bit only.
    • ScalingRatio / PerfQualityValue: never used for anything.
    • Intensity above 1: clamped.
  • A runtime-side reduced-resolution path with guided upsample exists, but it is dead code: its scale is fixed at 1.0. Downscaling must stay app-side.

  • Architecture. U-Net-style encoder/decoder: conv + windowed-attention (Swin, 1/2/4/8 heads at 32-256 ch) stages, split 16-head Swin at 512 ch, a 1024-ch ViT bottleneck, and a mirrored decoder. "Small" keeps the bottleneck and cuts the repeated blocks per stage.
  • Quantisation. The honest tench weights already look FP8-quantised (few distinct byte values in the large matrices). That fits "Quantize_With_Teacher": quantisation-aware training, no quantisation at load time.
  • Precision. Both runtimes append _fp8 to every kernel name and set activation dtype 2 for both models (310.9.16 FUN_1800572f0; 310.8 FUN_180032e20).
  • Memory. The work pool is set by the runtime, not the model: 310.9.16 needs about 527 MB at 4K for either model, 310.8 needs 728 MB. By working scale, 310.8 / 310.9.16:

The network output is a residual: x = enc(Color) + k·net, decoded as clamp(x·8 + 0.5, 0, 1), then blended with the warped history by a learned sigmoid weight (post-block PTX, ~l.13895-14125).

The final blend has two paths:

  • Fused into the last network kernel: ..._simple_blend (no mask), ..._control_mask, plus ..._full_rect variants when the rect is the whole texture. Picked by FUN_18001d2e0, rect test in FUN_18001d660. Used when the grade is the identity and there is no UI correction.
  • cg2r_post_process_kernel: dispatched by FUN_18001ca00 with 376 bytes of parameters. It handles the grade, UI correction, and the (dead) guided upsample.

6. Runtime-side reduced resolution and guided upsample (dead code)

310.9.16 contains a complete reduced-resolution path (local_816, l.19225-19268 and 19819-19923):

  • the network runs at floor(W·s + 0.5) × floor(H·s + 0.5);
  • the full-resolution Color/Backbuffer is kept as the high source (copied to dlssnr_guided_high_source_scratch, RGBA16F, if it aliases the output);
  • in cg2r_post_process_kernel, a 17×17×12-byte transferTile per 16×16 tile carries low-resolution deltas in Oklab (log-L ratio clamped ±2 and faded below L = 0.1, plus Δa/Δb), upsampled bilinearly onto the high source. That is the same idea as OptiScaler-NR's guided residual enlargement (Transfer 5), in Oklab and not edge-aware.

It is unreachable. P+0x124 is only written at parser initialisation (1.0, l.20203, disassembly 0x18001a12e) and clamped, so P+0x120 is always 0. DLSSNR.ScalingRatio is only written by the callback (l.14441) and never read. 310.8 ships the same transferTile code but also hard-wires the network size.

Corrections

  • FUN_1800176c0 is called (state, mgr, &P) (l.19403); the first arg is the per-feature state (featureNode+8). Offsets +0x170.. are relative to that state. It does not compare Intensity. CERTAIN.
  • P is 0x160 bytes; P+0x128..+0x15c = 14-float colour-grade vector; P+0x11c never written. CERTAIN.

Q1 Style

  • Read unclamped into P+0xec (l.20519-20525); EvaluateFeature clamps with an unsigned compare against the descriptor style count = 3 (registry entry +0x2c): Style >= 3 -> 2 (negative also -> 2) (l.19388-19394; FUN_18001f640 l.24188; again FUN_180021df0 l.26376-26385). CERTAIN.
  • Network input: Style/128 -> pre-block kernel param +184 -> constant input channel 10 (l.26414 -> FUN_1800620c0 l.75030 -> FUN_180083ee0 -> FUN_1800834b0 l.99528; pre PTX l.80-82,168). Both registry entries enable it (+0x28 = 1). CERTAIN.
  • Also selects a colour grade: FUN_18001d8a0 (l.22743) looks up the style in 8 slots per registry entry; FUN_18001d6d0 (l.22679) writes value x clamp(LocalToneStrength,0,1) into P+0x128..; applied in cg2r_post_process_kernel. Data (CERTAIN):
    • Style 0: no grade
    • Style 1: exposure -0.1 EV, contrast -0.25 (flatter), saturation -10 %
    • Style 2: saturation -15 %
    • slots 3-8 empty; nothing hidden selectable.
  • Grade engine has 14 controls (params +316..+371, host l.22327-22334; order from PTX l.720-1372): black point, white point, temperature, tint, exposure 2^v, contrast (smoothstep S-curve), 5-band per-channel tone curve, gamma c^(2^-v), HSL saturation x(1+v), saturation curve s^(2^-v). The styles use only three. Not reachable through parameters.
  • An active grade forces the post-process pass (output clamped [0,1], alpha 1, fused blend off). A Style change resets temporal history.

Q2 Strengths

Input channels per pixel (pre PTX l.130-610), CERTAIN: | ch | content | |---|---| | 0-2 | Gaussian noise (Box-Muller, seeded by x, y, frame) | | 3 | 1.0 | | 4-6 | colour, encoded (c-0.5)0.125 | | 7-9 | history: Catmull-Rom at uv + mvscale/size; copy of colour if no MVec / no valid history / Reset | | 10 | Style/128 | | 11 | Tone x mask.g | | 12 | AutoMask on: 1.0; off: structure x mask.b | | 13 | skin (or structure if skin < 0); -1 when AutoMask off | | 14 | structure; -1 when AutoMask off | | 15 | 0 |
